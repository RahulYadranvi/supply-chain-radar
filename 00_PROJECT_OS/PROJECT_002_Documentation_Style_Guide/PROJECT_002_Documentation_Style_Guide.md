## Chapter 1 — Documentation Philosophy

Supply Chain Radar documentation is treated as product infrastructure rather than notes.

Every document must be reproducible, version controlled, searchable, printable, and generated automatically through DOCS_OS.

### Core Principles

| Principle | Description |
|-----------|-------------|
| Single Source of Truth | Markdown is the master source. |
| Human First | Documentation is written for humans before machines. |
| Consistent Design | Every document uses the same typography, spacing, colors, and components. |
| Version Controlled | Every significant change is tracked through Git. |
| Modular | Components are reusable across every department. |
| Printable | HTML and PDF must maintain visual consistency. |

### Documentation Objectives

- Create long-term company knowledge.
- Eliminate duplicate information.
- Make onboarding possible through documentation.
- Keep every department synchronized through one documentation system.

### Source of Truth Hierarchy

1. Markdown (`.md`)
2. JSON Metadata (`version.json`)
3. DOCS_OS Builder
4. Generated HTML
5. Generated PDF

No generated document may be edited manually.

## Chapter 2 — Page Layout System

Every generated document follows the Apple Charcoal layout system.

### Layout Structure

1. Hero Section
2. Metadata Card
3. Navigation Sidebar (future)
4. Main Content
5. Footer
6. Version Information

### Page Width

| Screen | Width |
|--------|------|
| Desktop | 1200px |
| Tablet | 1000px |
| Mobile | 100% |

### Section Rules

- One H1 per document.
- H2 starts a new major chapter.
- H3 introduces subsections.
- Every chapter is separated by a divider.
- Every chapter begins with spacing token XL.
